# Comment Sicko review aid

Use this as a focused checklist inside the assigned independent review when a change adds or edits code comments. It is not a separate reviewer role, review gate, or source of task status; the configured reviewer remains the one owner of the review decision.

- Check that each comment is accurate against the current code and names the reason or invariant that is not obvious from the code.
- Flag redundant narration, stale claims, speculative TODOs, and comments that duplicate a canonical policy or documentation rule.
- Do not request comments solely to increase comment count. A documented invariant or tricky constraint may need one concise explanation.
- Send findings and evidence to the configured reviewer; do not create a parallel findings ledger or accept work.
